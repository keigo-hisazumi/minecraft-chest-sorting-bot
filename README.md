# minecraft-chest-sorting-bot

指定したチェストのアイテムを、周囲のチェストへ振り分け続ける Minecraft BOT です。

## 主な機能

- Minecraft Java Edition のサーバーに BOT として接続し、切断されたら再接続する
- チャットコマンドで整理元の指定チェストを登録する（指定がなければ一番近いチェストを登録する）
- チャットコマンドで触れてはいけないチェストを除外する
- 登録内容と開始の状態を保存し、再起動後も引き継ぐ
- 周囲のチェストの中身を調べ、アイテムを動かさずに振り分けの計画を表示する
- 指定チェストのアイテムを、専用チェストと混合チェストへ振り分け、整理先の中身も入れ替える
- 整理を開始すると、指定チェストを 30 秒ごとに確認して整理し続ける
- チャットコマンドで BOT をプレイヤーのそばへ呼び寄せ、現在位置を確認する

## 使い方

1. Minecraft Java Edition 1.21.11 のテスト用サーバーを起動する（サーバーの条件は [仕様書](./docs/spec.md) の「動作環境」を参照する）
2. `.env.example` を `.env` にコピーし、接続先を設定する
3. `npm start` で BOT を起動する
4. クライアントから同じサーバーに入り、BOT が「SortBot 起動」と発言することを確かめる
5. 指定チェストの近くで、`sort chest <x> <y> <z>` と発言して指定チェストを登録する
6. 動かしてはいけないチェストを `sort exclude <x> <y> <z>` で除外する
7. `sort plan` で振り分けの計画を確認する
8. `sort start` で整理を開始する。範囲内の除外していないチェストは、すべて中身が入れ替わる

## チャットコマンド

命令は、BOT 自身を除くすべてのプレイヤーから受け付けます。

| コマンド | 動作 |
| --- | --- |
| `sort chest <x> <y> <z>` | 指定した座標のチェストを指定チェストとして登録する。登録し直すと上書きする |
| `sort exclude <x> <y> <z>` | 指定した座標のチェストを除外する。指定チェストは除外できない |
| `sort start` | 整理を開始する（下の「整理の動作」を参照）。指定チェストがない場合は一番近いチェストを登録するので、もう一度発言する |
| `sort stop` | 整理、調査、移動を中止する |
| `sort status` | 状態、指定チェスト、除外したチェストを答える |
| `sort plan` | 指定チェストと周囲のチェストを順に開いて中身を調べ、振り分けの計画を表示する（下の「振り分けの計画」を参照） |
| `sort come` | 発言したプレイヤーが今いる場所のそばへ移動する。移動中はブロックを壊さず、足場も置かない |
| `sort pos` | BOT の現在地の座標を答える |

- 対象は通常のチェストだけです。大きなチェストは、どちらの座標を指定しても 1 つのチェストとして扱います
- BOT の周囲で読み込まれていない座標は登録できません
- 一番近いチェストは、BOT から水平 32 ブロック、上下 8 ブロックの範囲で探します
- 登録内容は、接続先とディメンションごとに `data/state.json` へ保存します（Git の対象外）
- 除外を取り消すコマンドはありません。取り消すときは、BOT を停止して `data/state.json` の `excluded` から該当する座標を削除します
- ワールドを作り直した場合は、`data/state.json` を削除します
- `data/state.json` が壊れている場合、BOT は起動しません

## 振り分けの計画

`sort plan` は、指定チェストから水平 32 ブロック、上下 8 ブロックの範囲にある、除外していないチェストを調べます。アイテムは動かしません。

- チャットでは要約を知らせます。アイテムごとの割り当て先などの詳細は `data/plan.txt` に書き出し、コンソールにも表示します
- 「廃棄予定」は、整理を実行した場合に専用チェストに入りきらず捨てることになる数です。残したいアイテムがあるチェストは、`sort exclude` で除外します
- 開けないチェストや行けないチェストは、理由を知らせて計画から外します
- 調査中は、`sort stop`、`sort status`、`sort pos` 以外のコマンドを受け付けません
- 計画は、足りないチェストを作り、単体チェストを大きなチェストに広げた場合のものです。チェストを置く場所があるかは確認しません

## 整理の動作

`sort start` で開始すると、範囲内を調査して、指定チェストのアイテムから順に移します。指定チェストから移すものがなくなると、整理先どうしの中身を入れ替えます。

- 合計が最大スタック数の 3 倍以上のアイテムは、アイテムごとの専用チェストへ、それ以外は混合チェストへ入れます
- 一度専用チェストを作ったアイテムは、少なくなっても同じチェストへ入れます
- その後は指定チェストを 30 秒ごとに確認し、中身が変わると整理します。開けないチェストがあった場合は、約 5 分後にやり直します
- チェストの作成、設置、拡張と、アイテムの廃棄はしません
  - 専用チェストには、今ある大きなチェストだけを使います。足りないアイテムは今の場所に残して知らせます
  - 専用チェストに入りきらないアイテムは、今の場所に残します。保護対象は、空いているチェストがあればそこへ移します
- BOT のホットバー（9 枠）は食料などの持ち物に使え、中身を動かしません。**残りの 27 枠にあるアイテムは、チェストへ移します**
- 整理中に `sort stop` した場合、運んでいる途中のアイテムは BOT が持ったままになり、次の `sort start` で続きを行います
- 切断や再起動のあとは、開始の状態なら整理を再開します。以前の版で保存した開始の状態は引き継ぎません
- 次の確認を待っている間に `sort come` で呼び寄せても、次の確認で指定チェストへ戻ります
- BOT が死亡した場合は、整理を停止して場所を知らせます。落としたアイテムは回収しません

## 技術スタック

- Node.js
- mineflayer（Minecraft BOT ライブラリ）
- mineflayer-pathfinder（経路探索と移動）
- vec3（座標計算）

## 開発

### 必要な環境

- Node.js 22 以降
- Minecraft Java Edition のサーバーとクライアント（動作確認用）

### コマンド

```bash
npm ci          # 依存関係のインストール
npm start       # BOT を起動する
npm test        # テストを実行する
npm run build   # src/ と scripts/ の構文を検査する
```

## ディレクトリ構成

```text
.
├── src/
│   ├── index.js          # BOT のエントリーポイント（接続と再接続）
│   ├── config.js         # 接続設定（環境変数から読み込む）
│   ├── commands.js       # チャットコマンドの解釈
│   ├── controller.js     # コマンドの実行
│   ├── chests.js         # チェストの判定と検索
│   ├── navigation.js     # BOT の移動
│   ├── survey.js         # チェストの中身の調査
│   ├── items.js          # 保護対象の判定
│   ├── plan.js           # 振り分けの計画
│   ├── planreport.js     # 計画と整理結果の表示
│   ├── moves.js          # アイテムの移し先の判断
│   ├── sorter.js         # アイテムの移動
│   └── state.js          # 登録情報の保存
├── scripts/
│   └── check-syntax.js   # 構文検査（CI の build で実行）
├── docs/
│   └── spec.md           # 仕様書
└── .env.example          # 接続設定の雛形
```

## デプロイ

デプロイはありません。BOT は手元の PC で起動し、Minecraft サーバーに接続して動かします。
